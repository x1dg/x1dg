# Задача: Проанализировать кодовую базу и создать иерархическую структуру AGENTS.md

## Контекст и принципы

Вы поможете создать **иерархическую систему AGENTS.md** для этой кодовой базы. Это критически важно для эффективной работы AI-агентов по кодингу с минимальным расходом токенов.

### Основные принципы:

1. **Корневой AGENTS.md — ЛЁГКИЙ** — только универсальные указания и ссылки на подфайлы
2. **Иерархия «ближайший побеждает»** — агенты читают AGENTS.md, ближайший к редактируемому файлу
3. **JIT-индексация (Just-In-Time)** — указывать пути/globs/команды, а НЕ полное содержимое
4. **Эффективность по токенам** — короткие, практичные указания вместо энциклопедической документации
5. **AGENTS.md в подпапках содержат БОЛЬШЕ деталей** — специфичные паттерны, примеры, команды

## Ваш процесс

### Фаза 1: Анализ репозитория

Сначала проанализируйте структуру кодовой базы и предоставьте:

1. **Тип репозитория**: Monorepo, multi-package или простой одиночный проект?
2. **Основной технологический стек**: языки, фреймворки, ключевые инструменты
3. **Основные директории/пакеты**, для которых нужен свой AGENTS.md:
   - Приложения (например, `apps/web`, `apps/api`, `apps/mobile`)
   - Сервисы (например, `services/auth`, `services/transcribe`)
   - Пакеты/библиотеки (например, `packages/ui`, `packages/shared`)
   - Воркеры/джобы (например, `workers/queue`, `workers/cron`)
4. **Система сборки**: pnpm/npm/yarn workspaces? Turborepo? Lerna? Или простая?
5. **Настройка тестирования**: Jest, Vitest, Playwright, pytest? Где лежат тесты?
6. **Ключевые паттерны для документирования**:
   - Паттерны организации кода
   - Важные соглашения (именование, стили, коммиты)
   - Критичные файлы, которые служат хорошими примерами
   - Антипаттерны, которых следует избегать

Представьте это в виде **структурированной карты** перед генерацией любых AGENTS.md файлов.

### Фаза 2: Создание корневого AGENTS.md

Создайте **лёгкий корневой AGENTS.md** (~100–200 строк максимум), который включает:

#### Обязательные разделы:

**1. Снимок проекта (Project Snapshot)** (3–5 строк)

- Тип репо (monorepo/простой)
- Основной технологический стек
- Примечание, что у подпакетов есть свои AGENTS.md файлы

**2. Команды настройки на корневом уровне (Root Setup Commands)** (5–10 строк)

- Установка зависимостей (на корневом уровне)
- Сборка всего
- Проверка типов всего
- Запуск всех тестов

**3. Универсальные соглашения (Universal Conventions)** (5–10 строк)

- Стиль кода (TypeScript strict? Prettier? ESLint?)
- Формат коммитов (Conventional Commits?)
- Стратегия веток
- Требования к PR

**4. Безопасность и секреты (Security & Secrets)** (3–5 строк)

- Никогда не коммитить токены
- Куда класть секреты (паттерны `.env`)
- Обработка PII, если применимо

**5. JIT-индекс — карта директорий (JIT Index - Directory Map)** (10–20 строк)

Структура вида:

```
## JIT Index (что открыть, а не что вставлять)

### Структура пакетов
- Web UI: `apps/web/` → [см. apps/web/AGENTS.md](apps/web/AGENTS.md)
- API: `apps/api/` → [см. apps/api/AGENTS.md](apps/api/AGENTS.md)
- Auth-сервис: `services/auth/` → [см. services/auth/AGENTS.md](services/auth/AGENTS.md)
- Общие пакеты: `packages/**/` → [см. packages/README.md для деталей]

### Быстрые команды поиска
- Поиск функции: `rg -n "functionName" apps/** packages/**`
- Поиск компонента: `rg -n "export.*ComponentName" apps/web/src`
- Поиск API-маршрутов: `rg -n "export const (GET|POST)" apps/api`
```

**6. Definition of Done** (3–5 строк)

- Что должно пройти перед готовностью PR
- Минимальный чеклист

### Фаза 3: Создание AGENTS.md для подпапок

Для КАЖДОГО основного пакета/директории из Фазы 1 создайте **подробный AGENTS.md**, который включает:

#### Обязательные разделы:

**1. Идентичность пакета (Package Identity)** (2–3 строки)

- Что делает этот пакет/приложение/сервис
- Основной tech/framework для ЭТОГО пакета

**2. Настройка и запуск (Setup & Run)** (5–10 строк)

- Команда установки (если отличается от корневой)
- Команда dev-сервера
- Команда сборки
- Команда тестов
- Команды lint/typecheck

**3. Паттерны и соглашения (Patterns & Conventions)** (10–20 строк)

**ЭТО САМЫЙ ВАЖНЫЙ РАЗДЕЛ**

- Правила организации файлов (куда что класть)
- Соглашения об именовании, специфичные для этого пакета
- Предпочитаемые паттерны с **примерами файлов**:

  ```
  - ✅ ДЕЛАТЬ: Использовать функциональные компоненты, как `src/components/Button.tsx`
  - ❌ НЕ ДЕЛАТЬ: Использовать class-компоненты, как `src/legacy/OldButton.tsx`
  - ✅ Формы: Копировать паттерн из `src/components/forms/ContactForm.tsx`
  - ✅ API-вызовы: Использовать обёртку `src/lib/api/client.ts`, см. пример в `src/hooks/useUser.ts`
  ```

**4. Ключевые точки / важные файлы (Touch Points / Key Files)** (5–10 строк)

Укажите самые важные файлы для понимания этого пакета:

```
- Логика auth: `src/auth/provider.tsx`
- API-клиент: `src/lib/api.ts`  
- Типы: `src/types/index.ts`
- Конфиг: `src/config.ts`
```

**5. Подсказки JIT-индекса (JIT Index Hints)** (5–10 строк)

Специфичные команды поиска для этого пакета:

```
- Найти React-компонент: `rg -n "export function .*" src/components`
- Найти хук: `rg -n "export const use" src/hooks`
- Найти обработчики маршрутов: `rg -n "export async function (GET|POST)" src/app`
- Найти тесты: `find . -name "*.test.ts"`
```

**6. Частые подводные камни (Common Gotchas)** (3–5 строк, если применимо)

- «Auth требует префикс `NEXT_PUBLIC_` для клиентской стороны»
- «Всегда использовать импорты `@/` для абсолютных путей»
- «Миграции БД нужно запускать перед тестами: `pnpm db:migrate`»

**7. Проверки перед PR (Pre-PR Checks)** (2–3 строки)

Специфичная для пакета команда перед созданием PR:

```
pnpm --filter @repo/web typecheck && pnpm --filter @repo/web test && pnpm --filter @repo/web build
```

### Фаза 4: Особые соображения

Для каждого AGENTS.md файла также учитывайте:

**A. Дизайн-система / UI-пакет**

Если есть дизайн-система или UI-библиотека:

```markdown
## Design System
- Компоненты: `packages/ui/src/components/**`
- Использовать design tokens из `packages/ui/src/tokens.ts` (никогда не хардкодить цвета)
- См. галерею компонентов: `pnpm --filter @repo/ui storybook`
- Примеры:
  - Кнопки: Копировать `packages/ui/src/components/Button/Button.tsx`
  - Формы: Копировать `packages/ui/src/components/Input/Input.tsx`
```

**B. База данных / слой данных**

Если есть сервис с БД:

```markdown
## Database
- ORM: Prisma / Drizzle / TypeORM
- Схема: `prisma/schema.prisma`
- Миграции: `pnpm db:migrate`
- Seed: `pnpm db:seed`
- **НИКОГДА** не запускать миграции в тестах; использовать скрипт `test-db`
- Подключение: через singleton `src/lib/db.ts`
```

**C. API / Backend-сервис**

```markdown
## API Patterns
- REST-маршруты: `src/routes/**/*.ts`
- Auth middleware: `src/middleware/auth.ts` (применять к защищённым маршрутам)
- Валидация: Использовать Zod-схемы в `src/schemas/**`
- Обработка ошибок: Все ошибки бросать как `ApiError` из `src/lib/errors.ts`
- Пример endpoint: См. `src/routes/users/get.ts` для полного паттерна
```

**D. Пакет тестирования**

```markdown
## Testing
- Unit-тесты: `*.test.ts` рядом с исходниками
- Интеграционные тесты: `tests/integration/**`
- E2E-тесты: `tests/e2e/**` (Playwright)
- Запуск одного теста: `pnpm test -- path/to/file.test.ts`
- Покрытие: `pnpm test:coverage` (цель >80%)
- Мокать внешние API через `src/test/mocks/**`
```

## Формат вывода

Предоставьте файлы в таком порядке:

1. **Сводка анализа** (из Фазы 1)
2. **Корневой AGENTS.md** (полный, готовый к копированию)
3. **Каждый AGENTS.md подпапки** (по одному, с путём к файлу)

Для каждого файла используйте такой формат:

```
---
File: `AGENTS.md` (root)
---
[полное содержимое здесь]

---
File: `apps/web/AGENTS.md`  
---
[полное содержимое здесь]

---
File: `services/auth/AGENTS.md`
---
[полное содержимое здесь]
```

## Ограничения и проверки качества

Перед генерацией проверьте:

- [ ] Корневой AGENTS.md меньше 200 строк
- [ ] Корневой файл ссылается на все sub-AGENTS.md
- [ ] Каждый подфайл содержит конкретные примеры (реальные пути к файлам)
- [ ] Команды готовы к copy-paste (без плейсхолдеров, если это неизбежно)
- [ ] Нет дублирования между корневым и подфайлами
- [ ] JIT-подсказки используют реальные паттерны из кодовой базы (ripgrep, find, glob)
- [ ] Каждый «✅ ДЕЛАТЬ» имеет реальный пример файла
- [ ] Каждый «❌ НЕ ДЕЛАТЬ» ссылается на реальный антипаттерн или legacy-файл
- [ ] Pre-PR проверки — одна команда для copy-paste
